# 派活单模板

每个子任务一份。六项必填，外加看板摘录。改派时整份原样转给下一个模型，只在开头加一行“改派自 <原模型>，原因 <限额或报错原文>”。

```markdown
# 派活单：<一句话标题>

你是执行者，在独立的工作树里干活。主控负责验收、提交和合并。自己做，不要再开子任务。
如果你认为范围、做法或完成标准不对：先交异议，不动手，回执只写异议。

## 1. 目标
<一两句，做成什么样>

## 2. 范围内文件
- <路径>

## 3. 范围外文件
- <不许碰的路径或类别>
- 不提交、不推送；改动留在工作树里。

## 4. 完成标准
<一条能通过的命令>

## 5. 预算
思考深度 <low/medium/high>；预计 <N> 分钟；卡住超过 20 分钟就停下，在回执里说卡在哪。

## 6. 谁来审
<审查者模型；和作者不是同一家>

## 看板摘录
- 用户原话（逐字，只放和本子任务有关的）：
- 已定决策：
- 别的执行者的结论：
<没有看板的任务：只放用户原话和相关结论。给审查者的摘录：不放作者对自己改动的评价，只放用户原话、已定决策、代码和测试输出。>

## 回执格式（最后一条消息照这个写）
1. 改了哪些文件（路径）。
2. 完成标准命令原始输出的末尾。
3. 异议（没有就写“无”；有异议时只写这一项，不动手）。
4. 用户直接对我说的话（原样，以及我因此改了什么；没有就写“无”）。
```
