# 圆桌

同一个问题由三家模型各给一份独立意见：主控一份，另外两家各一份。

## 开

主控在下列任一情况自动开，开之前用一句话告诉用户：

1. 做错了难以撤回、且各方案代价差别大的决定，如架构选型、数据模型、对外接口。
2. 审查第一轮后，作者和审查者仍谈不拢。
3. 用户点名要开。

## 不开

1. 走“直接答或直接做”的任务。
2. 跑一条命令或测试就能分出对错的问题。

## 做法

1. 主控先写下自己的看法，再派出，避免被别家的回答带着走。
2. 把同一份问题和看板摘录并行派给另外两家（用派活单模板，范围内文件为空，只读）。各家互相看不到回答。
3. 每份回答不超过约 200 字，只写三项：结论、理由、最大的风险。
4. 汇总时分开列：共识、分歧、主控的建议。不把分歧抹平。
5. 谁来定：涉及不可逆操作或会改变目标的分歧交用户定；其余由主控定。结果记进看板。

## 限制

- 同一个决定只开一次。
- 审查分歧只问还没参与的那一家，它的意见就是第二轮；两轮不过交用户定。
- 省额度模式下只问一家。
